# Встановлення і запуск

## Клонувати репозиторій
```
git clone <repo-url>

cd wtg_spain_test

docker compose up --build -d

docker compose exec php php artisan key:generate

docker compose exec php php artisan migrate --seed
```

Після цього API доступне на http://localhost:8080.

Команда ```php artisan queue:work --tries=3 --timeout=90``` запускається в окремому контейнері, тому вручну виконувати не треба (на проді краще налаштовувати такі речі через supervisor)

У .env за замовчуванням QUEUE_CONNECTION=database — Job складаються в таблицю jobs і обробляються воркером вище.

Тести використовують окрему тестову БД (DB_DATABASE з phpunit.xml), щоб не займати дані з робочої бази.

# Ідемпотентність імпорту

Імпорт побудований так, щоб повторне надсилання того самого запиту ніколи не створювало дублікатів і не запускало обробку вдруге.

Ключ ідемпотентності — унікальна пара (supplier_id, external_import_id) на рівні БД.

# Алгоритм у ImportService::handle()

Шукаємо існуючий Import за парою ```supplier_id, external_import_id``` через ```firstOrCreate()```.
Якщо запис вже існував — просто повертаємо його без додаткових операцій, такий самий запит не буде впливати на систему. 
Якщо запис новий — диспатчимо ProcessImportJob.
Якщо два ідентичні запити прийдуть одночасно, обидва можуть пройти перевірку first() до того, як перший встигне закомітити create(). У такому разі другий запит зловить QueryException від БД і дочитає вже створений запис замість того, щоб повернути помилку.

Окремо від ідемпотентності імпорту — правило оновлення офера, якщо ```supplier_id, offer.external_id``` вже існує в іншому імпорті, то ```Offer::updateOrCreate()``` всередині ```ProcessImportJob``` оновлює дані існуючого офера замість створення дубліката
